# 小米路由器 3G（R3G）固件编译方案

> 所属总览：[固件编译方案.md](../../../固件编译方案.md)


## 7.1 目标与产物

| 项目 | 值 |
|---|---|
| 设备 | 小米路由器 3G **标准版**（R3G，MT7621A / 128MB NAND / 256MB RAM） |
| 目标 | `ramips/mt7621`，profile `xiaomi_mi-router-3g`，架构 `mipsel_24kc` |
| 工具链 | `mipsel_24kc_gcc-12.3.0_musl` |
| 版本 | OpenWrt 23.05.6 `r24232-539228933c`，内核 5.15.189 |
| 源码树 | `~/openwrt-23.05.6-r3g`（独立于 x86 树，软链共用 `~/openwrt-23.05.6/dl`） |
| 一键脚本 | `firmware-build/devices/r3g/build-firmware-r3g.sh`（本机型目录独立） |
| 输出目录 | 构建机 `~/firmware-out/r3g-<YYYYmmdd-HHMM>/`；回传工作区 `firmware/`（不入库） |

产物：

```text
openwrt-ramips-mt7621-xiaomi_mi-router-3g-squashfs-sysupgrade.bin   已是 OpenWrt 后的升级包
openwrt-ramips-mt7621-xiaomi_mi-router-3g-squashfs-kernel1.bin      原厂首次安装：内核分区
openwrt-ramips-mt7621-xiaomi_mi-router-3g-squashfs-rootfs0.bin      原厂首次安装：根文件系统
openwrt-ramips-mt7621-xiaomi_mi-router-3g-initramfs-kernel.bin      可选：TFTP/串口救砖
openwrt-ramips-mt7621-xiaomi_mi-router-3g.manifest
```

刷机步骤见工作区 `R3G刷机教程.md`。

## 7.2 与 x86 方案的差异

1. **独立源码树**：首次运行脚本时用 `rsync` 从 `~/openwrt-23.05.6` 复制源码，排除
   `/build_dir`、`/staging_dir`、`/tmp`、`/bin`、`/dl`、`/.git`（只匹配根目录，避免把
   `package/base-files/files/bin` 这类同名子目录误删），再软链共享 `dl`。现有 x86 工具链
   与产物不受影响。
2. **内核模块集合不同**：去掉 x86 专用的 `kmod-i2c-i801`、`kmod-i2c-piix4`、
   `kmod-i2c-designware-*`；保留与平台无关的 `kmod-i2c-ch341`（CH341A 走 USB）。
3. **设备相关包**：由 `xiaomi_mi-router-3g` profile 自动带入 `kmod-mt7603`、`kmod-mt76x2`、
   `kmod-usb3` 等。
4. **只产出 R3G 镜像**，不生成 x86 镜像。

## 7.3 包与配置

脚本在 `make defconfig` 前确保以下选项为 `=y`：

```text
kmod-usb-core kmod-usb-serial kmod-usb-serial-ch341 kmod-usb-serial-cp210x
kmod-usb-serial-ftdi kmod-usb-serial-pl2303 kmod-usb-acm
kmod-i2c-core kmod-i2c-ch341 i2c-tools usbutils picocom
ca-bundle libustream-openssl uclient-fetch
ucode ucode-mod-fs ucode-mod-math ucode-mod-ubus ucode-mod-uci uhttpd uhttpd-mod-ucode
luci luci-base luci-mod-admin-full luci-proto-ipv6 luci-proto-ppp
mmdvmhost dmrgateway mmdvm-dashboard dmrstream
```

`mmdvmhost` / `dmrgateway` / `mmdvm-dashboard` / `dmrstream` / `i2c-ch341` 五个包现在只在本机型目录
（`firmware-build/devices/r3g/packages/`）维护，每次编译前由脚本同步进源码树。

> 由于源码树已包含 `feeds/` 与 `package/feeds/`，R3G 树不需要重新执行
> `feeds update/install`。若换用全新源码树，仍需先跑一次。

## 7.4 编译

```sh
ssh xy@192.168.8.200 '~/firmware-build/build-firmware-r3g.sh'
```

- 首次运行会创建独立源码树并编译 `mipsel_24kc` 工具链，耗时较长
- 之后为增量编译，只重编有改动的包（例如仪表盘）并重新打包镜像
- 脚本最后把镜像、manifest、buildinfo、`kmod-i2c-ch341` ipk、`SHA256SUMS`
  收集到 `~/firmware-out/r3g-<时间戳>/`

可覆盖的环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BASE_SRC` | `~/openwrt-23.05.6` | 作为复制来源的现有源码树 |
| `WORKDIR` | `~/openwrt-23.05.6-r3g` | R3G 源码树 |
| `JOBS` | `8`（统一值） | 并行编译数，脚本已固化为 8 |
| `OUTDIR` | `~/firmware-out/r3g-<时间戳>` | 产物输出目录 |

## 7.5 LuCI 与仪表盘的 80 端口

固件同时安装 LuCI 与 MMDVM 仪表盘，二者默认都监听 80。仪表盘包的 uci-defaults
（`90-mmdvm-dashboard`）在**首次启动**时做了两件事：

1. 若 LuCI 主站点仍在默认的 `80` / `443`，改为 `8080` / `8443`（自定义端口不动）
2. 创建 `uhttpd.dashboard` 站点，监听 80，`cgi_prefix=/api`，`home=/www-dash`

结果：

- MMDVM 仪表盘：`http://<设备IP>/`
- LuCI：`http://<设备IP>:8080/`

已刷过旧版固件的设备不会回溯生效，需手动执行一次：

```sh
uci set uhttpd.main.listen_http='0.0.0.0:8080'
uci add_list uhttpd.main.listen_http='[::]:8080'
uci commit uhttpd && /etc/init.d/uhttpd restart
```

## 7.6 设备侧差异

- 默认 LAN 地址是 `192.168.7.1`（脚本会改写 `config_generate`，不是原厂的 `192.168.31.1`，也避开常见上游 `192.168.8.x`）
- 主机名默认 `MMDVM-OpenWrt`，时区默认 `Asia/Shanghai`（`CST-8`），由 `mmdvm-dashboard` 的 `96-mmdvm-defaults` 在所有目标上统一设置
- 无线默认开启：出厂默认 AP（原 `LEDE` / `OpenWrt`）改名为 `MMDVM-OpenWrt`，2.4G/5G 同名、开放无密码；没有任何 AP 配置时在 2.4G 射频上新建。需要加密请自行在 LuCI 中修改
- `kmod-i2c-ch341` 由包自动写入 `/etc/modules.d/`；屏幕驱动还需要 `i2c-dev`：

```sh
echo i2c-dev > /etc/modules.d/i2c-dev
```

- MMDVM 调制解调器（CH340）对应 `/dev/ttyUSB0`，CH341A 对应 `/dev/i2c-0`

## 7.7 标准编译与发布流程（下次照此执行）

> 已按 2026-11-20 成功发布 V0.624 的过程固化。核心原则：**沿用现有
> `~/openwrt-23.05.6-r3g` 源码树做增量编译，不要删除或重建**，因为双内核槽补丁
> `R3G_DUAL_KERNEL` 只存在于该树中。

#### 1. 同步本机型目录到构建机

R3G 构建树已独立：工作区 `firmware-build/devices/r3g/`，构建机对应 `~/mmdvm-devices/r3g/`。
每次把整个目录上传（含 `packages/`、`VERSION`、脚本）：

```powershell
tar -cf .tools\r3g-dev.tar -C firmware-build\devices r3g
.tools\pscp.exe -batch -pw <密码> -hostkey <构建机hostkey> .tools\r3g-dev.tar xy@192.168.8.200:/tmp/r3g-dev.tar
.tools\plink.exe -batch -ssh -pw <密码> -hostkey <构建机hostkey> xy@192.168.8.200 "mkdir -p ~/mmdvm-devices && tar -xf /tmp/r3g-dev.tar -C ~/mmdvm-devices"
```

- 构建机账号 `xy@192.168.8.200`，密码见工作区 `.askpass8.cmd` / `.askpass.cmd`
- 首次连接先接受 hostkey，之后固定使用同一值
- 不要用本机文件覆盖构建机的 `dl/`、`build_dir/`、`staging_dir/`

#### 2. 编译

```sh
cd ~/mmdvm-devices/r3g
setsid sh build-firmware-r3g.sh </dev/null >/tmp/r3g-build.log 2>&1 &
```

- 增量编译通常 3~5 分钟，`tail -f /tmp/r3g-build.log` 观察
- 产物在 `~/firmware-out/r3g-<YYYYmmdd-HHMM>/`
- 版本号取自本目录 `VERSION`，发版前只改这一个文件

#### 3. 产物校验

```sh
# 双内核槽补丁仍在
grep -c R3G_DUAL_KERNEL ~/openwrt-23.05.6-r3g/target/linux/ramips/mt7621/base-files/lib/upgrade/platform.sh
# 镜像结构应为 CONTROL / kernel / root
tar tf ~/firmware-out/r3g-<时间戳>/openwrt-ramips-mt7621-xiaomi_mi-router-3g-squashfs-sysupgrade.bin | head
# 版本与校验值
sha256sum ~/firmware-out/r3g-<时间戳>/openwrt-ramips-mt7621-xiaomi_mi-router-3g-squashfs-sysupgrade.bin
```

解包确认三样东西真的进了镜像（V0.630 起每次都查，避免"编了但没打进去"）：

```sh
cd /tmp && rm -rf chk && mkdir chk && cd chk
tar xf ~/firmware-out/r3g-<时间戳>/openwrt-ramips-mt7621-xiaomi_mi-router-3g-squashfs-sysupgrade.bin
~/openwrt-23.05.6-r3g/staging_dir/host/bin/unsquashfs4 -d root -f sysupgrade-xiaomi_mi-router-3g/root >/dev/null
cat root/etc/mmdvm/fw.version            # 必须是本次新版本
md5sum root/usr/sbin/dmrstreamd          # 应与 build_dir 里的二进制 sstrip 后一致
md5sum root/www-dash/app.html            # 应与 dashboard/index.html 一致
ls root/etc/rc.d/ | grep dmrstream       # 必须有 S* 启动链接
```

#### 4. 发布 OTA

1. 把 sysupgrade 镜像和 `fw-xiaomi_mi-router-3g.json` 下载到本机 `.tools/`
2. 在 Gitee 仓库 `xyinmaster/mmdvm-openwrt-ota` 创建发行版：
   - tag：`fw-<版本>`（如 `fw-V0.624`）
   - 通过 `POST /repos/xyinmaster/mmdvm-openwrt-ota/releases` 创建，
     `access_token` 取自 `git credential fill`（本机已存 Gitee 凭据）
3. 通过 `POST .../releases/<release_id>/attach_files` 上传镜像（`curl -F file=@...`）
4. 更新仓库 `fw/xiaomi_mi-router-3g.json`：

```json
{
  "version": "V0.xxx",
  "versionName": "V0.xxx",
  "board": "xiaomi,mi-router-3g",
  "target": "ramips/mt7621",
  "url": "https://gitee.com/xyinmaster/mmdvm-openwrt-ota/releases/download/fw-<版本>/<镜像文件名>",
  "sha256": "<sha256>",
  "size": <字节数>,
  "notes": "<更新说明>"
}
```

5. 提交并推送 `mmdvm-openwrt-ota` 的 `main` 分支
6. 验证：

```sh
curl -sL -o NUL -w "%{http_code} %{size_download}" "https://gitee.com/xyinmaster/mmdvm-openwrt-ota/releases/download/fw-<版本>/<镜像文件名>"
curl -sL "https://gitee.com/xyinmaster/mmdvm-openwrt-ota/raw/main/fw/xiaomi_mi-router-3g.json"
```

返回 `200` 且大小与清单一致才算发布成功。

#### 5. 归档与收尾

- 把镜像和清单复制到工作区 `ota/dist/fw/`（本地镜像仓库，不入库）
- 清理 `.tools/` 下的临时 tar、镜像副本、临时 clone
- 通知用户在仪表盘「系统 → 固件更新」里手动检查、下载、安装；助手不代刷

#### 注意事项

- 镜像约 10.9MB，设备 OTA 需要 `/tmp` 至少 13MB 可用（脚本会检查）
- **版本号必须严格大于设备当前 `/etc/mmdvm/fw.version`**，相同则设备判定「无需升级」；只改 `www-dash/VERSION` 一处
- 清单文件必须 UTF-8 **无 BOM**：发布后取首字节应为 `123`（`{`）；`Set-Content -Encoding utf8` 会加 BOM，设备会报「无法获取更新清单」
- 不要执行 `make clean` 或删除 `~/openwrt-23.05.6-r3g`，否则双内核槽补丁和增量缓存都会丢失
- 若发布后需要修正，删除旧附件（`DELETE .../attach_files/<id>`）后重新上传，并同步更新清单中的 `sha256`
- 同一个版本号要同时发 GitHub 备源（`1083808255/dashboard-ota` 的 `fw/`，url 用 ghproxy 形式），主源被墙时设备才能回退
