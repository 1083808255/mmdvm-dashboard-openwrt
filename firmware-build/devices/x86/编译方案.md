# x86/64 固件编译方案

> 所属总览：[固件编译方案.md](../../../固件编译方案.md)


整套方案固化在两处（内容一致，关键文件已核对 MD5）：

- 工作区 `firmware-build/`
- 构建机 `~/firmware-build/`

```text
firmware-build/devices/x86/
├── build-firmware-x86.sh  一键编译脚本
├── config.seed            固件 .config（6762 行，整套包选择与内核选项）
├── feeds.conf.default     feeds 源与固定 commit
├── VERSION                本机型固件版本
├── packages/              固件包源码（本机型独享）
│   ├── mmdvmhost/         含 OLED/HD44780 与 x86 I2C 适配层
│   ├── dmrgateway/
│   ├── mmdvm-dashboard/
│   └── i2c-ch341/         CH341A 驱动
└── 编译方案.md            本文档
```

构建机上对应目录为 `~/mmdvm-devices/x86/`，同步方式：

```powershell
tar -cf .tools\x86-dev.tar -C firmware-build\devices x86
.tools\pscp.exe -batch -pw <密码> -hostkey <构建机hostkey> .tools\x86-dev.tar xy@192.168.8.200:/tmp/x86-dev.tar
.tools\plink.exe -batch -ssh -pw <密码> -hostkey <构建机hostkey> xy@192.168.8.200 "mkdir -p ~/mmdvm-devices && tar -xf /tmp/x86-dev.tar -C ~/mmdvm-devices"
```

一键执行：

```sh
ssh xy@192.168.8.200 '~/mmdvm-devices/x86/build-firmware-x86.sh'
```

或登录构建机后直接运行：

```sh
~/mmdvm-devices/x86/build-firmware-x86.sh
```

脚本流程：

1. `.config` 不存在时用 `config.seed` 恢复（`RESET_CONFIG=1` 强制覆盖现有配置）；
   缺少 `feeds.conf` 时用 `feeds.conf.default` 补上
2. 把 `packages/` 下的 `mmdvmhost`、`dmrgateway`、`mmdvm-dashboard`、`i2c-ch341`
   同步到源码树（`i2c-ch341` 放到 `package/kernel/`）
3. 确保关键包已启用后 `make defconfig`，再执行 `make -j$(nproc)`
4. 把镜像、manifest、buildinfo、kmod ipk 收集到 `~/firmware-out/<YYYYmmdd-HHMM>/`，
   并生成 `SHA256SUMS`

如果是全新源码树，首次需先执行一次
`./scripts/feeds update -a && ./scripts/feeds install -a`。

可覆盖的环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WORKDIR` | `~/openwrt-23.05.6` | OpenWrt 源码树 |
| `JOBS` | `8`（统一值） | 并行编译数，脚本已固化为 8 |
| `OUTDIR` | `~/firmware-out/<时间戳>` | 产物输出目录 |

编译完成后，刷写 `~/firmware-out/<时间戳>/openwrt-x86-64-generic-squashfs-combined-efi.img.gz`
解压出的镜像即可，该镜像同时包含屏幕 I2C 驱动、`i2c-tools` 与 `kmod-i2c-ch341`。
