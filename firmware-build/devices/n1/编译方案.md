# 斐讯 N1 固件编译与发布方案

> 所属总览：[固件编译方案.md](../../../固件编译方案.md)

## N1.1 机型与产物

| 项目 | 值 |
|---|---|
| 设备 | 斐讯 N1（Amlogic S905D / 2GB RAM / 8GB eMMC） |
| 目标 | `amlogic/mesongx`，profile `phicomm_n1`，架构 `aarch64_cortex-a53` |
| 工具链 | `aarch64_cortex-a53_gcc-12.3.0_musl` |
| 源码树 | Lean `coolsnowwolf/lede`，固定 commit `dca9ba875e319cb05c25fe3a1d092833bf457ccc`，内核 **5.15.225** |
| 一键脚本 | `firmware-build/devices/n1/build-firmware-n1.sh` |
| 构建机路径 | `~/fwbuild-n1/n1/build-firmware-n1.sh`（含 `packages/`、`patches/`、`kernel-patches/`、`VERSION`） |
| 输出目录 | `~/firmware-out/n1-<YYYYmmdd-HHMM>/` |

产物（整机镜像，非 sysupgrade tar）：

```text
openwrt-amlogic-mesongx-phicomm_n1-squashfs-sysupgrade.img.gz   gzip 压缩的 MBR 磁盘镜像，含 3 个分区
openwrt-amlogic-mesongx-phicomm_n1.manifest                       安装包清单
SHA256SUMS                                                        产物整体校验
fw-phicomm_n1.json                                                OTA 清单
fw-amlogic_mesongx.json                                           OTA 清单（board/target 两种键）
profiles.json                                                     目标 profile 元数据
```

> 注意：N1 的 sysupgrade 镜像是 **MBR 磁盘镜像**（gzip 压缩），不是其他机型的 tar 格式。
> 解包验证根文件系统时先 `gzip -dc *.img.gz | dd of=p2.img bs=512 skip=139264 count=524288`（分区 2，squashfs 根），
> 再 `unsquashfs -d root p2.img etc/mmdvm/fw.version ...`。

## N1.2 脚本自动处理的内容

构建脚本 `build-firmware-n1.sh` 固化了 3 个设备专属补丁 + 基础配置：

| 补丁 | 位置 | 作用 |
|---|---|---|
| **`patches/003-seccomp-loongarch-fallback.patch`** | 构建时拷贝到 `package/system/procd/patches/` | procd 2026-06-17 版引用的 `AUDIT_ARCH_LOONGARCH64` 是内核 5.18+ 宏，5.15 下未定义；把 loongarch 分支包进 `#ifdef` 避免编译失败 |
| **`kernel-patches/001-dts-s905d-fix-high-load.patch`** | 构建时覆盖 lede 自带的同名补丁 | lede `dca9ba87` 自带的 001 对内核 5.15.225 已过期（上游已把 `meson-gxl-s905d-p230.dts` 的中断 29→25 并加注释）；本目录版仅移除 `eee-broken-1000t;` 行，中断修复已由上游吸收 |
| **`sed` 注释 `mesongx.mk` 两行** | 目标树 `target/linux/amlogic/image/mesongx.mk` | 注释掉 `onethingcloud_oes` / `oes-plus` 设备行；OES DTS 用 5.18+ 内核宏 `IRQID_GPIOZ_14`，在 5.15 下编译 DTB 失败 |
| **sed 固定 `KERNEL_PATCHVER:=5.15`** | `target/linux/amlogic/Makefile` | N1 的 CH341 驱动是 5.15 回移版；防止上游切到 6.6 |

其他通用步骤（所有机型一致）：

1. 执行 `feeds update -a && feeds install -a`（全新克隆后 luci-base 不在 feeds/，会导致 `po2lmo: command not found` 等链式失败）
2. 同步 `mmdvmhost`、`dmrgateway`、`dmrstream`、`i2c-ch341` 到源码树 `package/`
3. **仪表盘走单源**：`FW_ROOT` 解析到 `firmware-build/packages/mmdvm-dashboard/` 后复制，叠加 `devices/n1/dashboard-override/`（若存在）
4. 写 `files/etc/mmdvm/fw.version` ← `VERSION` 文件
5. 写 `files/etc/sysupgrade.conf`：保留 5 个 mmdvm 配置（dashboard.json、livecfg.json、dashboard-ota.json、MMDVM.ini、DMRGateway.ini）
6. 写 `files/etc/config/network` + `files/etc/config/dhcp`：单网口 DHCP 客户端 + WiFi 开放 AP
7. 生成 `.config` + `make defconfig`，然后 `make -j8`
8. 收集产物 + 生成双 JSON（`fw-phicomm_n1.json`、`fw-amlogic_mesongx.json`，内容相同）+ `SHA256SUMS`

## N1.3 编译

```powershell
tar -cf .tools\n1-dev.tar -C firmware-build\devices n1
scp .tools\n1-dev.tar xy@192.168.8.200:/tmp/n1-dev.tar
ssh xy@192.168.8.200 "mkdir -p ~/fwbuild-n1 && tar -xf /tmp/n1-dev.tar -C ~/fwbuild-n1 && mv ~/fwbuild-n1/n1 /tmp/n1-$$bak 2>/dev/null; (cd ~/fwbuild-n1 && tar -xf /tmp/n1-dev.tar && chmod +x n1/build-firmware-n1.sh)"
```

构建机上运行：

```sh
cd ~/fwbuild-n1/n1
JOBS=8 nohup sh ./build-firmware-n1.sh > /tmp/n1-build.log 2>&1 &
```

脚本内部已固定 `JOBS=8`，显式覆盖仅是强调。产物在 `~/firmware-out/n1-<时间戳>/`。

**排查要点**：并行编译日志会把真实错误藏起来，遇到 `ERROR: target/linux failed to build` 时改用单线程详查：

```sh
cd ~/lede-n1
make target/linux/compile V=s -j1 2>&1 | tail -60
# 或完整：
make world V=s -j1 2>&1 | tail -80
```

## N1.4 发布 OTA

1. 在 Gitee `xyinmaster/mmdvm-openwrt-ota` release `fw-V0.660` 上传资产，**重命名为** `n1-V0.660-squashfs-sysupgrade.img.gz`
2. 在 Gitee 仓库 `fw/` 目录新建 **两个** JSON：

```json
// fw/phicomm_n1.json（board "phicomm,n1" → dashboard 用 replaceAll(board,',','_') 找这个文件）
{
  "version": "V0.660",
  "versionName": "V0.660",
  "board": "phicomm,n1",
  "target": "amlogic/mesongx",
  "url": "https://gitee.com/xyinmaster/mmdvm-openwrt-ota/releases/download/fw-V0.660/n1-V0.660-squashfs-sysupgrade.img.gz",
  "sha256": "<sha256>",
  "size": <字节数>,
  "notes": "<更新说明>"
}
```

```json
// fw/amlogic_mesongx.json（target "amlogic/mesongx" → dashboard 用 replaceAll(target,'/','_') 找这个文件）
// 内容与 phicomm_n1.json 完全相同，只是键名不同
```

3. 提交并推送 Gitee `main`
4. 同步 GitHub 备源：把同名镜像放入 `1083808255/dashboard-ota/fw/`，两个 JSON 同样新建、`url` 改成 `https://ghproxy.net/https://raw.githubusercontent.com/1083808255/dashboard-ota/main/fw/n1-V0.660-squashfs-sysupgrade.img.gz`
5. **验证**：Gitee release + GitHub raw + ghproxy 三处下载 sha 必须全部匹配

## N1.5 镜像内验证（必须解最终镜像，staging_dir 里看不到 files/ 覆盖）

```sh
# 1. 解压根文件系统分区
IMG=openwrt-amlogic-mesongx-phicomm_n1-squashfs-sysupgrade.img.gz
gzip -dc "$IMG" | dd of=p2.img bs=512 skip=139264 count=524288 2>/dev/null
unsquashfs -d root p2.img

# 2. 版本号 + livecfg 软链 + sysupgrade.conf
cat root/etc/mmdvm/fw.version           # 必须是 V0.660
ls -la root/www-dash/api/livecfg       # 必须 → api.uc
cat root/etc/sysupgrade.conf           # 必须保留 5 个 mmdvm 配置

# 3. manifest 核心包 & 禁用包
grep -E '^mmdvmhost |^dmrgateway |^mmdvm-dashboard |^dmrstream |^kmod-i2c-ch341 ' \
  openwrt-amlogic-mesongx-phicomm_n1.manifest  # 5 个都要有
grep -E 'air780e-monitor|mmdvm-board-7628|xray-core|luci-app-ssr-plus' \
  openwrt-amlogic-mesongx-phicomm_n1.manifest   # 必须全 0 行（禁选项）
```

## N1.6 已知坑

| 现象 | 根因 | 对策 |
|---|---|---|
| `make target/linux/prepare` 报 `001-dts-s905d` Hunk FAILED | lede 自带 001 对内核 5.15.225 过期（上游已改中断号 29→25 并加注释） | `devices/n1/kernel-patches/001-dts-s905d-fix-high-load.patch` 覆盖之，仅保留「删 eee-broken 行」；脚本含 guard 自动检测替换 |
| `make package/system/procd/compile` 报 `AUDIT_ARCH_LOONGARCH64 undeclared` | procd 2026-06-17 版引用 5.18+ 宏 | `patches/003-seccomp-loongarch-fallback.patch`，脚本自动拷贝 |
| `make target/linux` 报 `meson-g12b-a311d-oes.dts:304` 语法错 | mesongx.mk 编译了 3 个设备的 DTB；OES 的 DTS 用了 5.18+ 宏 | sed 注释 `TARGET_DEVICES += onethingcloud_oes` 和 `..._oes-plus` |
| 全新克隆后 `po2lmo: command not found`（`default-settings` 失败） | 缺 feeds 步骤 | 脚本已固化 `feeds update -a && feeds install -a` |
| `make resolve_btfids` 报 `libelf.h` 缺失 | 构建机没装 libelf/pahole | 脚本已关闭 `CONFIG_KERNEL_DEBUG_INFO_BTF` |
| 构建机磁盘 100% | 多棵 `build_dir` 叠加 | 清理非活跃机型的 `build_dir` / `tmp`，**不要删 `dl/`** |
| ghproxy 首次下载只有 199B 错误页 | 未命中缓存（`X-Cache: MISS`）的瞬时返回 | 重试即可；raw.githubusercontent 始终 OK |
