# 红米 AX5 固件编译与发布流程

> 所属总览：[固件编译方案.md](../../../固件编译方案.md)


> 以 2026-11-21 发布 AX5 V0.628 的实际过程为准。AX5 与 R3G 共用
> `~/firmware-build/packages`，但**目标、源码树、脚本和设备树完全不同**，不要混用。

## 8.1 机型与产物

| 项目 | 京东云版（主用） | 普通版 |
|---|---|---|
| 机型 | `redmi_ax5-jdcloud`（IPQ6000 / eMMC） | `xiaomi_rm1800`（IPQ6000 / 128MB NAND） |
| 目标 | `qualcommax/ipq60xx` | 同左 |
| 源码 | Lean `coolsnowwolf/lede`，内核 6.18 | 同左（另有 LibWrt 6.12 变体） |
| 构建脚本 | `~/firmware-build/build-firmware-ax5.sh` | `~/firmware-build-ax5/build-firmware-ax5-std.sh`（旧目录，使用前先同步包） |
| 产物 | 约 32MB 的 `*-squashfs-sysupgrade.bin` | 同左 |
| 发布清单 | `fw/redmi_ax5-jdcloud.json` | `fw/xiaomi_rm1800.json`（未发布则新建） |

产物还包括 `factory.bin`（京东云版）/ `factory.ubi`（普通版）和 `initramfs-uImage.itb`，
其中 factory 镜像**仅用于 U-Boot 救砖**，日常升级只用 sysupgrade。

## 8.2 源码树与脚本

| 项目 | 值 |
|---|---|
| 主脚本 | `~/firmware-build/build-firmware-ax5.sh` |
| 源码树 | `~/lede-ipq60`（Lean，约 6.18 内核） |
| 包目录 | `~/firmware-build/packages`（与 x86 / R3G 共用） |
| AX5 覆盖文件 | `~/firmware-build/targets/ax5/`（设备树、镜像脚本、ipq60xx base-files） |
| 旧独立树 | `~/firmware-build-ax5/`（11-18 的 V0.610 基线，**不要用于日常编译**） |
| 普通版脚本 | `~/firmware-build-ax5/build-firmware-ax5-std.sh` |
| LibWrt 变体 | `~/firmware-build-ax5/build-firmware-ax5-libwrt.sh`（`~/libwrt`，6.12 + NSS） |

## 8.3 脚本自动处理的内容

1. 同步 `mmdvmhost`、`dmrgateway`、`mmdvm-dashboard`、`dmrstream`、`i2c-ch341` 到源码树
2. 写入 `/etc/mmdvm/fw.version`（取 `www-dash/VERSION`）
3. 覆盖设备树 `targets/ax5/ipq6000-ax5-jdcloud.dts`（USB3/USB2、I2C2/3/6、去掉 console）
4. 覆盖 `scripts/json_overview_image_info.py`（修正 profiles.json 生成）
5. 覆盖 `targets/ax5/ipq60xx-base-files/`：
   - `lib/upgrade/platform.sh`：sysupgrade 前把小米 U-Boot 固定到当前 rootfs 槽，
     并置 `flag_boot_success=1`、`flag_try_sys1_failed=8`、`flag_try_sys2_failed=8`
   - `etc/init.d/bootcount`：每次成功开机后重新确认启动成功并复位失败计数器
6. MMDVM.ini 串口改为 `/dev/ttyMSM0`（SoC UART3 接双工板）
7. 覆盖 `/etc/inittab`，关闭 UART 登录 shell
8. 默认 LAN 地址改为 `192.168.7.1`
9. 生成 `.config`（`CONFIG_TARGET_qualcommax_ipq60xx_DEVICE_redmi_ax5-jdcloud=y`、
   USB、文件系统、ucode、uhttpd、zram 等）并编译
10. 编译后从 sysupgrade 包提取 `kernel` / `root` 校验大小：kernel 不得超过
    6,291,456 字节（p16），rootfs 不得超过 118,509,568 字节（p17），超限立即中止发布

## 8.4 编译

与 R3G 共用包目录，所以同步包的方式相同（见 7.7 第 1 步），同步一次
`~/firmware-build/packages` 即可同时供 R3G 和 AX5 使用。除 `packages/` 外，还要同步
`build-firmware-ax5.sh` 和 `targets/ax5/`，否则设备树或启动修复不会进入镜像。

```sh
cd ~/firmware-build
setsid sh build-firmware-ax5.sh </dev/null >/tmp/ax5-build.log 2>&1 &
```

- 产物在 `~/firmware-out/ax5-<YYYYmmdd-HHMM>/`
- 首次全量编译较久；之后增量约 5~10 分钟
- 版本号同样只改 `www-dash/VERSION`

校验：

```sh
# 启动修复必须已进入实际源码树
grep -n xiaomi_ax5jdcloud_pin_boot_slot ~/lede-ipq60/target/linux/qualcommax/ipq60xx/base-files/lib/upgrade/platform.sh
grep -n redmi,ax5-jdcloud ~/lede-ipq60/target/linux/qualcommax/ipq60xx/base-files/etc/init.d/bootcount
# 版本号在编译前由 www-dash/VERSION 决定，产物目录不会另存版本文件
sha256sum ~/firmware-out/ax5-<时间戳>/openwrt-qualcommax-ipq60xx-redmi_ax5-jdcloud-squashfs-sysupgrade.bin
ls -lh ~/firmware-out/ax5-<时间戳>/
```

## 8.5 发布 OTA

1. 在 Gitee `xyinmaster/mmdvm-openwrt-ota` 创建或复用发行版，tag `fw-<版本>`
2. 上传 sysupgrade 镜像，**资产重命名为** `ax5-<版本>-squashfs-sysupgrade.bin`
3. 更新 `fw/redmi_ax5-jdcloud.json`：

```json
{
  "version": "V0.xxx",
  "versionName": "V0.xxx",
  "board": "redmi,ax5-jdcloud",
  "target": "qualcommax/ipq60xx",
  "url": "https://gitee.com/xyinmaster/mmdvm-openwrt-ota/releases/download/fw-<版本>/ax5-<版本>-squashfs-sysupgrade.bin",
  "sha256": "<sha256>",
  "size": <字节数>,
  "notes": "<更新说明>"
}
```

4. 提交并推送 Gitee `main`
5. 同步 GitHub 备源 `1083808255/dashboard-ota`：把同名镜像放入 `fw/`，并提交同名清单；
   备源清单仅 `url` 不同，指向
   `https://ghproxy.net/https://raw.githubusercontent.com/1083808255/dashboard-ota/main/fw/ax5-<版本>-squashfs-sysupgrade.bin`
6. 验证主备清单均返回新版本，镜像 URL 返回 `200` 且大小与清单一致；最后在设备执行
   `uclient-fetch -qO- http://127.0.0.1/api/fw?act=check`，确认 board/target 匹配且能解析新版本

## 8.6 注意事项

- **仅京东云版（eMMC）可刷 jdcloud 镜像**；普通版（NAND）和其他 AX5/AX6 变体分区
  不同，刷错会变砖
- 京东云版的 p16 `0:HLOS` 是唯一内核分区，p17 `rootfs` 是当前系统；p24 名为
  `overlay` 且为空，**不是可回滚的备用系统**。不要依赖 A/B 自动回滚，也不要手动清空
  p12 `0:APPSBLENV` 中的启动标志
- V0.628 起由上述 `platform.sh` 与 `bootcount` 自动维护 A/B 启动标志。从 V0.627 及更早
  版本首次升级时，旧系统尚不含升级前固定逻辑，建议刷写前先按当前 `flag_boot_rootfs`
  固定槽位并复位计数器；首次进入 V0.628 后由 `bootcount` 接管
- factory 镜像只用于 U-Boot 恢复，日常升级一律用 sysupgrade
- 串口已固定给双工板（`/dev/ttyMSM0`），不要恢复 UART 登录 shell
- 不要把 R3G 的双内核槽补丁、镜像或配置套到 AX5 上
- 当前线上版本：V0.629（2026-11-21），33,516,349 字节。V0.630/V0.631 只发布了 R3G 固件与仪表盘 OTA，AX5 下次发版时需按最新源码重编并递增版本
